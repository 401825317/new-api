# 安全排空补丁

此补丁默认关闭，独立于 Responses 故障重试。仅设置 `RELEASE_DRAIN_ENABLED=true` 后启用；同时配置至少 32 字符的随机 `RELEASE_DRAIN_TOKEN`。不修改数据库结构。

## 接口与发布顺序

管理接口仅绑定进程本机 `127.0.0.1:3001`，不能公开映射该端口。接口要求 `Authorization: Bearer <RELEASE_DRAIN_TOKEN>`。

- `POST /drain`：不可逆地停止接收新的 HTTP 请求和维护任务；返回 202 不表示已排空。
- `GET /status`：只读返回 active_work、pending_batch、pending_dashboard、failed、safe_to_stop，不返回密钥或原始数据库错误。
- 没有恢复接流、清除失败或强制停机接口。

先在 cf-global 将新请求切往健康 B 并核对缓存传播、实际落点，再向 A 发起排空。已经进入 A 的请求继续运行；异步退款、额度 Redis 更新、看板入队、渠道禁用和维护任务纳入计数。计数归零后才执行最终落库。

只有 safe_to_stop=true 才能向平台发出更新或暂停请求。SIGTERM 会进入同样的排空流程，但不能依赖平台终止宽限期：SIGKILL、机器故障、OOM 不能被应用拦截。这个补丁保证受控发布时的停止门禁，不是断电级持久队列。

## 数据库失败

批量更新的五类余额/用量变更放在同一事务中，严格检查每个目标行。事务成功后才清空缓存。看板更新同样采用事务，PostgreSQL 新版本实例间以事务 advisory lock 串行化看板写入。

失败时保留缓存并锁定失败状态。网络异常可能发生在数据库已经提交之后，因此不得自动重放这一批；需要独立核对数据库、账单与日志，不能直接重启清除失败状态。此版本故意不提供自动解锁。

启用后的数据库 Create/Update/Delete/Raw 执行失败、关键 Redis 额度写入失败或异步退款失败，都会阻止报告安全停机。错误记录本身不自动修复既有账务异常。

## 第一次上线的限制

旧官方 A 没有这些计数、失败锁定和排空接口；不能通过替换镜像给正在运行的旧进程补上保护。新版本通过测试不等于旧 A 已能安全停止。

第一次正式更新仍需独立证明旧 A 无新请求、所有在途及异步结算已完成、最后的批量与看板落库可核对。只有成功日志或固定等待时间不够。如果无法获得充分证据，保持旧 A 运行，不执行第一次停机。生产备份不得覆盖切换期间的新交易。

新旧版本短暂同库期间，旧版本看板写入不遵循新 advisory lock；本补丁不能追溯修复旧进程行为。首次发布必须单独审计这一兼容窗口。
